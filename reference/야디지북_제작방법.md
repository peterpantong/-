# 골프 야디지북, 이렇게 만들었습니다

AI에게 "야디지북 만들어줘"라고 하면 대개 실패합니다. 이 문서는 아난티 남해 야디지북을
실제로 만든 절차를 그대로 적은 것으로, 다른 골프장에도 같은 방법이 통합니다.

> 2026년 9월 2일 작업 기준입니다.

---

## 먼저, 왜 안 됐을까

막히는 지점은 보통 두 가지입니다. 하나는 **어떤 클로드를 쓰느냐**, 다른 하나는
**재료를 어디서 가져오느냐**입니다.

### 첫째 — 클로드 코드(터미널 버전)를 써야 합니다

이게 가장 흔한 원인입니다. 같은 클로드라도 버전에 따라 할 수 있는 일이 다릅니다.

| | 웹 · 앱 (claude.ai) | **클로드 코드 (터미널)** |
|---|---|---|
| 홈페이지 원본 HTML 받기 | 요약본만 읽음 | 통째로 받아 직접 파싱 |
| 도면 이미지 18장 내려받기 | 불가 | 가능 |
| 이미지 자르고 여백 다듬기 | 불가 | 가능 |
| PDF로 인쇄해 뽑기 | 불가 | 가능 |
| 결과를 파일로 저장 | 복사해서 직접 붙여야 함 | 폴더에 그대로 생성 |

야디지북 작업은 **이미지를 내려받아 자르는 과정이 절반**입니다. 웹·앱 버전에는 그 기능
자체가 없어서, 아무리 잘 시켜도 같은 결과가 나오지 않습니다. 대신 "이런 걸 만들어 드릴게요"
하고 텍스트로 흉내 낸 답이 돌아옵니다.

> **클로드 코드는 터미널에 설치해서 쓰는 버전입니다.** 구독 계정은 그대로 쓰고,
> 맥이면 터미널, 윈도우면 WSL이나 파워셸에서 돌립니다. 설치 후 작업할 폴더에서
> `claude`를 실행하면 됩니다.

### 둘째 — 공략을 지어내게 두면 안 됩니다

AI에게 코스 공략을 물으면 **그럴듯한 문장을 지어냅니다.** 학습 데이터에 그 골프장의
홀별 야디지나 벙커 위치가 들어 있을 리 없기 때문입니다. "3번 홀은 오른쪽에 벙커가 있으니
주의하세요" 같은 문장은 어느 골프장에나 붙일 수 있는 말이고, 실제로는 틀렸을 가능성이 큽니다.

그래서 야디지북의 성패는 글솜씨가 아니라 **원본 데이터를 어디서 가져오느냐**에 달려 있습니다.

### 이번 작업의 열쇠

아난티 남해 공식 홈페이지의 홀 이미지가 **사진이 아니라 정식 야디지 도면**이었습니다.

- 벙커마다 그린까지 남은 거리가 인쇄돼 있음
- IP 지점까지의 거리가 4개 티(BLACK/BLUE/WHITE/RED)별로 표기됨
- 100야드·150야드 라인이 그어져 있음
- 왼쪽에는 그린 확대도와 깊이 격자(0/10/20/30야드)

즉 **야디지북에 필요한 정보가 이미 다 그려져 있었습니다.** 할 일은 그걸 찾아서 받아오고,
읽기 좋게 다시 조판하는 것뿐이었습니다.

대부분의 국내 골프장 홈페이지가 이런 코스 안내 도면을 갖고 있습니다. **먼저 찾아보세요.**
없는 곳이라면 야디지북을 만들 게 아니라 현장에서 직접 측정해야 합니다.

## 준비물

| 항목 | 이유 |
|---|---|
| **클로드 코드 (터미널 버전)** | 앞에서 말한 그 이유입니다. 웹·앱 버전으로는 이 작업이 안 됩니다 |
| Python + Pillow | 도면 이미지를 자르고 여백을 다듬는 데 씁니다 |
| Chrome | PDF로 인쇄할 때 씁니다 |

`pip install pillow markdown` 정도면 충분합니다. Chrome은 이미 깔려 있을 테고,
파이썬도 맥이면 기본으로 들어 있습니다.

작업은 폴더 하나를 만들어 그 안에서 시작하면 됩니다. 도면 이미지와 데이터 파일,
결과물이 전부 그 폴더에 쌓입니다.

## 절차

### 1. 공식 코스 페이지를 찾습니다

골프장 이름 + "코스" 또는 "홀 안내"로 검색합니다. 예약 대행 사이트 말고 **골프장 공식
홈페이지**여야 합니다. 아난티 남해는 `ananti.kr/ko/namhae/NH0201`이었습니다.

### 2. 페이지를 요약하지 말고 통째로 받습니다

여기가 갈리는 지점입니다. AI의 웹 열람 기능은 페이지를 **요약해서** 보여주기 때문에
숫자가 빠지거나 뭉개집니다. 원본 HTML을 그대로 받아야 합니다.

```
curl -sL -A "Mozilla/5.0 ..." "https://골프장주소" -o course.html
```

받은 다음 이미지 주소만 뽑아봅니다.

```
grep -oE '(src|data-src)="[^"]*"' course.html | sort -u
```

### 3. 이미지를 실제로 열어봅니다

주소만 보고 판단하면 안 됩니다. 몇 장 내려받아 **눈으로 확인**하세요.
사진이면 야디지북 재료가 아니고, 도면이면 재료입니다.

아난티 남해는 홀마다 `1170×990` 크기 이미지 한 장에 왼쪽은 그린 확대도,
오른쪽은 홀 전체 도면이 붙어 있었습니다.

### 4. 홀 데이터를 HTML에서 뽑습니다

이미지만으로는 부족합니다. 파·핸디캡·티별 거리·공식 홀 해설이 HTML 안에 텍스트로
들어 있으니 함께 뽑습니다. 태그를 걷어내고 텍스트만 남기면 됩니다.

이 단계에서 **검산을 반드시 합니다.** 아난티 남해는 핸디캡이 1번부터 18번까지
정확히 한 번씩 나오는지 확인했고, 홀별 야디지 합계도 더해봤습니다.
합계가 7,130야드였는데 공식 소개문에는 7,244야드로 적혀 있었습니다.
**둘 중 하나를 고르고, 문서에 그 차이를 밝혀 두는 게 정직합니다.**

### 5. 도면 이미지를 다듬습니다

한 장에 붙어 있는 그린 확대도와 홀 도면을 좌우로 나누고, 흰 여백을 잘라냅니다.
여백을 안 자르면 화면에서 도면이 작게 보입니다.

```python
# 흰색이 아닌 픽셀의 경계를 찾아 그만큼만 남기는 방식
```

### 6. 데이터를 JSON 한 곳에 모읍니다

이게 나중에 크게 편해지는 부분입니다. 홀 정보를 `holes.json`, 여행 정보를 `travel.json`에
넣어두고 빌드 스크립트가 읽게 하면, **데이터를 한 번 고칠 때 웹·모바일·PDF·문서가 한꺼번에
갱신됩니다.** HTML에 숫자를 직접 적어 넣으면 나중에 네 군데를 따로 고쳐야 합니다.

홀 하나의 구조는 이렇게 잡았습니다.

```json
{
  "no": 4, "course": "OUT", "par": 3, "hdcp": 8,
  "yd": [157, 145, 124, 111], "m": [144, 133, 114, 102],
  "tag": "시그니처 · 바다 캐리 파3",
  "official": "공식 홈페이지 홀 해설 원문",
  "marks": [["그린 뒤 바위 절벽", "티에서 BLACK 176 / BLUE 153 ..."]],
  "tee": "티샷 공략", "second": "세컨드 공략", "green": "그린 공략",
  "caution": "한 줄 경고"
}
```

### 7. 공략은 도면에서 읽어 씁니다

여기서 AI를 제대로 씁니다. **"공략을 지어내라"가 아니라 "도면에 적힌 수치를 근거로 정리하라"**
고 시켜야 합니다. 실제로 쓴 문장은 이런 식입니다.

> 10m 내리막이라 캐리가 그대로 런으로 이어진다. 위험은 오른쪽 벙커 사선 하나뿐 —
> BLACK 기준 150~185yd 구간에 세 개가 겹쳐 있으니 페어웨이 왼쪽 절반만 보고 친다.

"150~185yd"는 도면에 인쇄된 숫자에서 나온 것입니다. 근거 없는 문장은 넣지 않습니다.

### 8. 하나의 소스로 여러 형태를 뽑습니다

- **웹 전체판** — 큰 화면에서 도면을 크게 보는 용도
- **모바일 필드판** — 라운드 중 폰으로 한 홀씩 넘기는 용도
- **PDF** — 인쇄해서 들고 다니거나 오프라인 보관
- **마크다운** — 지인에게 그냥 보내는 용도

## 걸렸던 함정들

**웹 열람 기능의 요약을 믿으면 안 됩니다.**
숫자가 빠지거나 이미지 주소를 추측으로 채웁니다. 원본 HTML을 받아 직접 확인하세요.

**이미지를 페이지에서 직접 불러오면 안 됩니다.**
공유용 웹 페이지(아티팩트 등)는 보안 정책상 외부 이미지를 차단합니다.
이미지를 base64로 파일 안에 심어야 합니다. 그러면 **파일 하나로 오프라인에서도 열립니다.**
남해처럼 통신이 약한 곳에서는 이 방식이 오히려 유리합니다.

**PDF에서 접힌 내용은 안 나옵니다.**
`<details>`로 접어둔 공식 해설이 PDF에서 통째로 빠졌습니다. 인쇄용 사본을 따로 만들어
펼친 상태로 바꾼 뒤 인쇄했습니다.

**PDF 페이지가 어긋납니다.**
홀 하나가 한 페이지에 안 들어가면 뒷장에 몇 줄만 남는 빈 페이지가 생깁니다.
인쇄용 글자 크기와 여백을 줄여 **홀당 한 페이지**로 맞췄습니다. 22페이지가 나왔습니다.

**색이 인쇄에서 빠집니다.**
`print-color-adjust: exact`를 넣지 않으면 도면 색이 날아갑니다.

**공식 표기와 실제 합계가 다릅니다.**
앞서 말한 7,244 대 7,130입니다. 이런 건 숨기지 말고 문서에 적어두는 편이 낫습니다.

**한글 파일명은 주소에서 깨져 보입니다.**
웹에 올릴 파일은 영문 이름으로 바꿔 두는 게 편합니다.

## 다른 골프장에 적용하려면

바꿔야 할 건 사실상 **데이터 파일 하나**입니다.

1. 그 골프장 공식 코스 페이지를 찾습니다
2. HTML을 받아 홀 데이터와 도면 이미지를 뽑습니다
3. `holes.json`을 새로 채웁니다
4. 빌드하면 웹·모바일·PDF·문서가 한 번에 나옵니다

도면이 없는 골프장이라면, 홀별 야디지 표만 있어도 스코어카드와 거리 정보까지는 만들 수 있습니다.
다만 벙커 위치나 그린 컨투어는 **없는 걸 지어내지 말아야** 합니다.

## 그대로 써도 되는 프롬프트

Claude Code 터미널에서 아래처럼 시키면 같은 흐름으로 진행됩니다.

```
○○골프장 야디지북을 만들어줘.

1. 공식 홈페이지 코스 페이지를 찾아서 HTML을 curl로 통째로 받아줘.
   웹 요약 말고 원본을 직접 파싱해야 해.
2. 홀별 파·핸디캡·티별 거리·공식 홀 해설을 뽑고,
   핸디캡이 1~18 한 번씩인지, 야디지 합계가 공식 표기와 맞는지 검산해줘.
3. 홀 이미지가 코스 도면인지 사진인지 실제로 열어서 확인해줘.
   도면이면 전부 받아서 그린 확대도와 홀 도면으로 분리하고 여백을 잘라줘.
4. 데이터는 holes.json 한 곳에 모으고, 빌드 스크립트가 그걸 읽어
   웹·모바일·PDF·마크다운을 만들게 해줘.
5. 홀별 공략은 도면에 인쇄된 수치를 근거로만 써줘.
   근거 없는 일반론은 넣지 마.
6. 이미지는 base64로 심어서 파일 하나로 오프라인에서 열리게 해줘.
7. PDF는 홀당 한 페이지로 맞춰줘.
```

마지막 두 줄이 특히 중요합니다. 이걸 빼먹으면 라운드 중에 안 열리는 페이지와
빈 페이지가 섞인 PDF가 나옵니다.
