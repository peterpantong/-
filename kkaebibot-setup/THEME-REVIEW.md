# 알짜테마 검토 워크플로

깨비봇이 테마주 스크리닝 결과를 뽑아 놓은 다음, **그 목록에서 재무가 받쳐주는 종목만
남기는** 작업의 절차. 스크리닝 자체가 아니라 스크리닝 결과를 걸러내는 단계다.

깨비봇을 수동으로 돌리든 작업 스케줄러로 자동 실행하든, 결과 파일이 나온 시점이
이 문서의 출발점이다.

> 이 문서는 조사·검토 절차를 정리한 것이지 투자 권유가 아니다. 매수·매도 판단은
> 본인이 한다. 실주문 자동화는 이 흐름에 넣지 않는다 (SETUP.md 4장 참고).

## 왜 별도 단계인가

테마 스크리닝은 보통 가격·거래량·뉴스 빈도로 잡는다. 재무 필터가 없으면
**테마에 편승만 한 부실 종목이 상단에 올라온다.** 급등 상위에 적자·자본잠식·
잦은 유상증자 종목이 섞이는 게 정상이다.

그래서 스크리닝 결과 → 하드 배제 → 실체 확인 → 재무 체크 순으로 좁힌다.
앞의 두 단계는 기계가, 마지막 판단은 사람이 한다.

## 0. 입력 준비

깨비봇 결과 파일에 최소한 아래 컬럼이 있어야 이후 단계가 자동화된다.
없으면 스크리너에 추가하는 게 먼저다.

| 컬럼 | 용도 |
|---|---|
| 종목코드 (6자리) | 공시·재무 조회 키 |
| 종목명 | 사람이 읽는 용도 |
| 시장 (KOSPI/KOSDAQ/KONEX) | 관리종목 요건이 시장별로 다름 |
| 테마명 | 왜 걸렸는지 |
| 편입 근거 (뉴스/공시 링크) | 3장 실체 확인의 출발점 |
| 시가총액 | 유동성·희석 판단 |
| 일평균 거래대금 | 유동성 |

결과 파일은 날짜를 붙여 남긴다. 나중에 "그때 왜 걸렀나"를 되짚을 수 있어야 한다.

```
data/screen/2026-08-28_theme.xlsx
```

## 1. 하드 배제 — 기계로 거른다

판단이 필요 없는, 걸리면 무조건 빼는 항목. 스크리너 뒤에 필터 함수로 붙여두면
매번 손댈 필요가 없다.

| 배제 기준 | 이유 |
|---|---|
| 관리종목·투자주의환기종목 지정 | 상장폐지 경로 |
| 거래정지·정리매매 | 진입 자체가 불가 |
| 감사의견 비적정 (한정·부적정·의견거절) | 재무제표를 믿을 수 없음 |
| 자본잠식 (부분 포함) | 관리종목 요건 |
| 최근 4개 분기 연속 영업손실 | 코스닥 관리종목 누적 요건에 접근 |
| 최대주주 변경 잦음 (최근 2년 2회 이상) | 껍데기 회사 신호 |
| 스팩(SPAC) | 사업 실체 없음 |
| 우선주 | 유동성·괴리율 문제, 테마 검토 대상 아님 |
| ETF·ETN·리츠 | 개별 종목 재무 검토가 성립 안 함 |
| 일평균 거래대금 기준 미달 | 못 빠져나옴 |

**우선주 제외는 코드에 이미 있는지 확인한다.** 스크리너에서 빠져 있으면 여기가 아니라
스크리너를 고치는 게 맞다.

## 2. 실체 확인 — 테마가 진짜인가

여기서 대부분이 걸러진다. 핵심 질문 하나다.

> **그 테마가 이 회사 매출로 잡히고 있나, 아니면 뉴스에만 있나?**

| 등급 | 판단 근거 |
|---|---|
| 실체 있음 | 해당 사업 매출이 재무제표에 구분 표시되고 비중이 유의미 |
| 초기 | 공급계약·수주 공시가 있고 금액이 명시됨 (시총 대비 비중 확인) |
| 편승 | MOU·업무협약·"검토 중"·보도자료만 있음 |
| 무관 | 회사가 직접 밝힌 적 없고 언론·커뮤니티 추측만 |

**MOU와 공급계약을 같은 무게로 보지 않는다.** MOU는 구속력이 없고, 테마 시즌마다
반복 공시되는 경우가 많다. 금액과 기간이 없는 계약 공시도 마찬가지로 취급한다.

## 3. 재무 체크 — 남은 종목만

1~2장을 통과한 소수에만 적용한다. 처음부터 전 종목에 돌리면 시간만 든다.

| 항목 | 보는 것 |
|---|---|
| 영업이익 | 최근 4분기 중 3분기 이상 흑자 |
| 영업현금흐름 | 흑자, 그리고 순이익과 방향이 같은가 |
| 부채비율 | 업종 평균 대비 |
| 이자보상배율 | 영업이익 ÷ 이자비용, 1 미만이면 이자도 못 냄 |
| 희석 이력 | 최근 3년 유상증자·CB·BW 발행액이 시총 대비 얼마나 되는가 |
| ROE | 추세 (한 해 튄 값인지 지속인지) |
| PER·PBR | 테마 급등분을 뺀 기준으로 |

**순이익 흑자인데 영업현금흐름이 적자면 멈춘다.** 매출채권·재고 증가로 만든
이익일 수 있다. 이건 자동으로 판정하지 말고 사람이 사업보고서를 본다.

**희석 이력은 테마주에서 특히 중요하다.** 테마로 주가가 뜬 직후 유상증자나 CB를
발행한 이력이 반복되면, 주가 상승이 자금조달 수단으로 쓰이고 있다는 뜻이다.

## 4. Claude Code 세션에서 돌리는 법

깨비봇 폴더에서 `claude`를 띄운 뒤, 단계별로 시킨다. 한 번에 다 시키지 말고
1장 → 2장 → 3장 순으로 끊어야 중간 결과를 눈으로 확인할 수 있다.

```
data/screen/2026-08-28_theme.xlsx 읽어서 1장 하드 배제 기준으로 거른 뒤
남은 종목과 빠진 종목을 사유와 함께 표로 보여줘

남은 종목들 편입 근거 링크를 훑어서 2장 등급(실체 있음/초기/편승/무관)을
매기고, 근거 문장을 그대로 인용해줘

'실체 있음'과 '초기'만 남겨서 3장 재무 항목을 채운 표를 만들고,
이자보상배율 1 미만이거나 영업현금흐름 적자인 건 따로 표시해줘

오늘 검토 결과를 data/review/2026-08-28.md 로 저장하고 커밋해줘
```

각 단계에서 **왜 걸렀는지 사유를 같이 남기게** 한다. 사유 없는 목록은 다음 날
다시 못 읽는다.

## 5. 자동화하지 않는 것

- **최종 매수·매도 판단** — 목록을 좁히는 데까지가 이 흐름의 끝이다.
- **실주문 실행** — SETUP.md의 경고대로, 주문 스크립트는 허용 목록에 넣지 않는다.
- **2장 등급 판정의 확정** — 자동으로 초안은 뽑되, '편승'과 '초기'의 경계는 눈으로 본다.

## 6. 기록 남기기

TWO-MACHINES.md에 적힌 대로, **대화 이력은 다른 PC로 안 따라간다.**
검토 결과는 반드시 파일로 남기고 커밋한다.

```
data/review/2026-08-28.md
```

그리고 기준이 바뀌면 (배제 항목 추가, 임계값 조정) `CLAUDE.md`에 반영한다.
다음 세션이 같은 기준으로 판단하려면 대화가 아니라 파일에 있어야 한다.

```powershell
git add -A
git commit -m "2026-08-28 테마 검토 - 12종목 중 3종목 잔존"
git push
```
